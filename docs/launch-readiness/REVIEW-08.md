# 실제 배포 문서·정책 불일치 검토 — 2026-10-26

PR #25의 exact-head READY 배포에서 실제 HTML 8개와 참조 JavaScript 한 개를 기존 Vercel 연결로 읽었다. 개인정보·약관 문구와 문의 구현의 불일치를 확인했다. 직접 Playwright 요청은 여전히 SSO로 이동하므로 브라우저·네트워크·저장소 검수를 통과로 표시하지 않는다.

- source head: `ccca758488fcd6605c456f10c9be26caaeb05286`; base: `c8c5489a662ae9aab354335483332116f1962072`. 시작 시 작업 폴더는 깨끗했고 PR #25는 Draft였다.
- Vercel deployment: `dpl_4K3LQqh8vqB8HsgbxMJqMqubpN5n`. 기존 연결의 `get_deployment`에서 READY와 위 commit SHA의 일치를 확인했다. 변경 가능한 브랜치 alias 대신 해당 배포의 고유 hostname을 검사했다.
- 고유 배포: `jsl-logistics-frontend-8nsgba35p-minbbbb1201s-projects.vercel.app`.
- 기존 팀 승인이 적용된 Vercel 연결의 `web_fetch_vercel_url`로 `/landing`, `/en/landing`, `/zh/landing`, `/vi/landing`, `/privacy`, `/terms`, `/en/privacy`, `/en/terms`에서 HTTP 200을 받았다. 실제 HTML이며 로컬 fixture나 가짜 API 응답으로 대체하지 않았다.

## 서버 렌더링에서 확인한 문의·링크

한국어 폼은 회사명·제목을 선택, 담당자명·이메일·내용을 필수로 표시한다. 동의 체크박스와 개인정보처리방침 링크가 있으며 초기 HTML의 입력·제출 버튼은 비활성이다. 안내는 온라인 문의 접수 준비 중이라는 내용이다. 이는 서버가 만든 초기 상태이며 클라이언트 고지 GET 성공 여부나 hydration 뒤 최종 상태를 확인한 결과는 아니다.

네 언어 landing의 폼 레이블은 해당 언어로 전달되고 개인정보 링크도 locale 경로를 사용한다. 한국어의 `/privacy`, `/terms`와 영어의 `/en/privacy`, `/en/terms`는 실제 200 및 문서 제목을 확인했다. 링크를 키보드로 활성화한 검사나 새 창 포커스 검사는 아니다. 한국어 초기 HTML에는 언어 선택·테마 설정 버튼의 이름도 있다. 메뉴 조작·테마 변경은 미검사다.

## PR #27과의 알려진 통합 조건

PR #25 단독 배포에서 영어·중국어·베트남어 landing 및 확인한 영어 법적 문서의 초기 `<html lang>`은 `ko`였다. 관련 파일은 `frontend/src/app/layout.tsx`와 `[locale]/layout.tsx`다. 문서 기본 언어는 보조 기술이 언어를 선택하는 정보이므로 [W3C의 Language of Page 설명](https://www.w3.org/WAI/WCAG22/Understanding/language-of-page.html)을 기준으로 확인할 항목이다.

이 항목은 이미 별도 [PR #27](https://github.com/MINBBBB1201/jsl-project/pull/27)의 locale 수정 범위에 있다. 조회한 PR #27 head는 `5c1c638b270ce36fda425fd1abdceecd9b248f2a`이고 PR #25에는 아직 포함되지 않았다. 메인에서 전달한 PR #27의 서버 언어·메뉴·테마·푸터 검수 결과를 이 회차의 실행 결과로 재사용하지 않는다. 새 중복 소스 결함으로 만들거나 PR #25에서 locale 소스를 수정하지 않았다. 최종 통합 head에서 다시 확인해야 한다.

## 실행하지 않은 검사와 변경 경계

- 기존 메인 브라우저 검수·잠금과 겹치지 않도록 새 브라우저·임시 접근 링크 호출을 잠시 멈췄다. 메인 해제 후 기존 연결의 문서 읽기를 마쳤다. 다른 세션의 잠금·서버·프로세스를 종료하지 않았다.
- 이번에는 새 브라우저를 시작하지 않았다. 기존 연결의 HTML 읽기 권한과 직접 브라우저 인증은 다른 경로이며, 후자는 직접 HTTP 진입에서 SSO가 확인됐다. 보호 정책 해제·계정 생성·새 우회 설정을 하지 않았다. 네이티브 `web_fetch`의 임시 접근 처리와 별도의 프로젝트 보호 설정 변경을 구분한다.
- 페이지별 실제 hydration, 언어 메뉴, 테마 변경, 키보드 이동·새 창 포커스, 15초 지연·스크롤·재방문 네트워크, 브라우저 cookie jar·localStorage·sessionStorage는 미검사다. 따라서 추적 없음·쿠키 동의 완료·배포 접근성 통과로 쓰지 않는다.
- 실제 문의 POST·업무 데이터 작성·운영 계정 생성은 하지 않았다. 가짜 응답도 사용하지 않았다. 기존 도구의 HTTP 진입 검사만 재사용했다.
- 앱·디자인·애니메이션·검수 도구·locale 소스는 바꾸지 않았다. 변경은 `docs/launch-readiness/**`의 보고·증빙뿐이다. 전체 build·lint·타입·DB·과거 16화면 검사는 이번에 재실행하지 않았다.
- 새 증빙 JSON·문서 링크·diff와 기존 앱 소스 해시를 확인한다. PR #25는 정책·운영·통합 검수 조건이 남아 Draft로 유지한다. main 병합·운영 배포는 하지 않았다.
