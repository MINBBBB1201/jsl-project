## 외부 입력 없이 이어갈 수 있는 범위

소스·미리보기 증빙을 연결하고 문의 검사를 재현할 수 있다. 기존 인증이 없으면 보호 배포의 실제 브라우저 검사는 진행할 수 없다. 이미지·문구·공유 UI 수정은 해당 소유자와 대상 파일을 먼저 조율한다. 회사 보유기간·책임자·사업 사실·자산 사용 허가는 코드 검사로 확정할 수 없다.

## 배포 네트워크 검사의 완료 기준

1. 검사할 head와 배포 주소를 연결하고 접근 가능한 기존 인증을 확인한다. 권한·보호 설정은 임의로 바꾸지 않는다.
2. 새 context, 15초 지연, 전체 스크롤, 언어·테마 변경, 재방문을 나눠 origin·요청 분류·쿠키 속성·저장 키의 변화를 기록한다.
3. 선택 서비스가 있으면 미선택·거부·허용·철회 후 실행 여부와 재방문 동작을 기록한다. 서비스가 없으면 그 검사 범위를 근거와 함께 적는다.
4. 문의는 폐기 가능한 API/DB에서만 제출한다. 운영 로그인·고객 데이터·원시 HAR·비밀값은 증빙에 넣지 않는다.
5. 최종 통합 head의 기능·접근성·API·저장·정책 불일치를 다시 확인한 뒤 PR 검토 상태를 결정한다. 회사 운영 고지 미승인 상태로 병합하지 않는다.
