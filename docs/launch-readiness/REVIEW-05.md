# 문의 재시도 복구와 출시 항목 조사 — 2026-10-24

미확정 문의의 요청 키가 새로고침 뒤에도 같은 탭에서 복구되도록 보완했다. 유닛 80건과 실제 문의 컴포넌트의 브라우저 검사 16조건·6흐름이 통과했다. 회사 운영 정책 승인과 실제 배포 검수는 완료하지 않았다.

- 실제 소스의 저장·외부 요청과 미확정 회사 입력은 [조사 결과](SOURCE-DATA-INVENTORY-20261024.md)에 따로 정리했다.

## 복구 동작과 수집 제한

저장하는 값은 버전, 무작위 요청 키, 요청 키를 섞은 SHA-256 비교값, 만료 시각이다. 이름·이메일·문의 원문·동의 상태를 저장하거나 자동 복원하지 않는다. 이용자는 새로고침 후 같은 내용을 입력하고 다시 동의해야 한다. 비교값은 암호문이나 익명 정보를 뜻하지 않는다.

복구 기간은 생성 때부터 30분이며 재시도해도 늘어나지 않는다. 만료 여부는 다음 접근 때 검사한다. 접수 확정 후 다음 제출은 새 문의 키를 사용한다. 저장소 삭제가 실패해도 같은 컴포넌트는 확정된 키를 다시 쓰지 않는다.

저장소 차단·용량 초과·Web Crypto 해시 실패 때는 현재 페이지의 메모리 재시도 보호를 유지한다. 이 경우 새로고침 복구는 보장하지 않는다. 저장소가 읽기만 되고 삭제·쓰기가 막힌 특이 환경에서는 새로고침 뒤 이전 메타데이터가 만료 전까지 남을 수 있다.

복구는 같은 탭·동일 앱 환경의 마지막 미확정 문의 1건을 대상으로 한다. 탭 종료·다른 기기·입력 변경·기간 만료 후의 중복 방지나 브라우저 저장소의 강제 삭제 시점은 보장하지 않는다. 서버 DB의 재시도 키 보유·삭제 정책과 이 30분 클라이언트 기간은 별개다.

[sessionStorage의 수명과 접근 제한](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage), [Web Crypto digest의 secure context 조건](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest)을 확인했다. 새 패키지는 추가하지 않았다.

응답 유실은 서버가 실제 저장한 뒤 응답만 중단했다. 새로고침 후 이메일과 동의가 비어 있는지 확인하고, 재입력·재동의 후 재접수해 DB 문서 수가 늘지 않는 것을 확인했다. 성공 후 저장소 메타데이터가 지워지는 것도 검사했다.

유닛 검사는 새 컴포넌트의 키 복구, 정규화한 입력, 다른 입력·언어, 만료, 잘못된 메타데이터, 저장소 차단, 확정 키 삭제 실패와 해시 실패를 포함한다. 저장 원문에 이름·이메일·문의·동의 필드가 없는지도 확인했다.

브라우저 검사는 기존 설치 Playwright·axe·Chrome·MongoDB 바이너리를 재사용했다. 공유 heavy-run 잠금을 단독 취득하고 물리·가상 메모리 기준을 확인한 뒤 실행했다. 임시 빌드·DB는 D:에 두었고 테스트 종료 후 브라우저·서버·DB와 자기 잠금을 정리했다. 고객 자료·운영 DB·운영 계정은 사용하지 않았다.

검사 요약은 [browser-summary.json](evidence/review-05/browser-summary.json), 화면은 [데스크톱 라이트](evidence/review-05/ko-light-desktop.png)와 [모바일 다크](evidence/review-05/ko-dark-mobile.png)에 있다. 영어 fixture 고지는 테스트 자료이며 승인된 회사 정책이 아니다.
