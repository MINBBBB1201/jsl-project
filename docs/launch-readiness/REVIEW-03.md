# 문의 화면·서버 연결 검토 — 2026-10-13

## 이번 변경

기존 ContactSection의 배치·채널을 보존하면서 서버가 승인한 언어별 수집·이용 고지를 불러온다. 담당자명·이메일·문의 내용은 필수, 회사명·제목은 선택이다. 고지에서 허용하지 않은 선택 항목은 비활성화하고 전송하지 않는다. 동의가 없거나 고지가 준비되지 않은 경우 접수할 수 없다.

실제 `/api/contact` 라우트가 동의·현재 고지 hash·요청 키를 검증하고 MongoDB에 저장한다. 접수 번호는 저널을 포함한 저장 확인 후에만 표시한다. 응답 유실 후 같은 화면에서 같은 내용을 재시도하면 기존 번호를 받는다. 고지가 바뀌면 새 안내에 다시 동의해야 하며 이미 저장된 문의의 원래 동의 증거는 바꾸지 않는다.

운영자 인앱 알림은 고객 이름·이메일을 복제하지 않고 접수 번호만 표시한다. 같은 번호의 알림은 고유 키로 중복을 막는다. 알림 실패는 접수 성공을 취소하지 않으며 같은 접수 재시도 시 알림을 다시 시도한다. 독립적인 알림 재시도 작업은 아직 없다.

## 운영 설정

`CONTACT_POLICY_PATH`는 UTF-8 JSON 파일을 가리킨다. 최상위 키는 `ko`, `en`, `zh`, `vi`이고 각 값은 승인된 운영 고지 또는 `null`이다. 예시 파일은 모두 `null`이며 접수를 활성화하지 않는다. 각 고지는 `kind: "operational"`, `approved: true`, `approvedBy`, `noticeId`, `effectiveDate`, `purpose`, `items`, `retentionDescription`, `refusalConsequence`, `privacyContact`가 필요하다. `items`에는 `contactName`, `email`, `message`가 포함되어야 한다. 선택 항목은 `companyName`, `subject`다.

파일 누락·잘못된 JSON·미승인·고지 누락 언어는 503으로 차단한다. 운영 라우트는 테스트 고지를 허용하는 옵션을 노출하지 않는다. 고지 변경은 운영 파일 교체와 서버 재시작을 함께 계획한다. 실제 보유기간·담당자·처리업체·삭제 운영은 제공 자료에서 확정하지 못했으므로 임의로 생성하지 않았다.

## 검증과 실제로 발견한 문제

- 서버 HTTP→폐기 가능한 MongoDB 17건 통과. 동시 제출, 재시도, 변경 내용 충돌, 고지·언어·미승인 차단, 최대 길이 한글, parser, 인덱스 누락, DB 프로세스 재시작, 알림 실패·실제 알림 중복 방지를 포함한다.
- 프론트 순수 로직을 포함한 유닛 70건 통과. 공개 고지 검증, 허용한 데이터만 전송, 안전한 접수 응답, 재시도 식별을 추가했다.
- 전체 frontend TypeScript 검사 통과. 기존 의존성을 읽기 전용으로 재사용하고 Next 이미지 타입을 포함하는 로컬 생성 파일로 검사했다.
- 변경한 backend 파일 ESLint와 전체 frontend ESLint 통과.
- 실제 문의 컴포넌트 4언어 × 라이트/다크 × PC/모바일 16조건에서 axe의 WCAG A/AA 자동 오류 0건, 가로 넘침 0건. 키보드 체크박스·필수 입력 오류 포커스, 접수/재전송, 응답 유실, 고지 변경 재동의, DB 저장 실패, 미승인 고지 차단의 6흐름을 확인했다. 캡처 4장과 결과는 `evidence/review-03`에 있다. 자동 검사만으로 전체 WCAG 적합성을 주장하지 않는다.
- 실제 ContactSection을 재사용한 작은 React/webpack 검증 번들을 만들었다. Next 라우팅 Link는 검증 어댑터이며 Next 서버 렌더링·수화·실제 배포 폰트 검증을 대체하지 않는다. 기존 CSS와 지역화 문구를 사용했다.
- Windows 테스트 DB 종료가 프로세스를 즉시 종료하여 이전의 비저널 저장이 유실되는 문제를 재현했다. `w: "majority", j: true` 저장 확인으로 수정하고 재시작 후 레코드·인덱스·번호 유지를 검증했다. replica failover·다중 지역 복구는 검사하지 않았다. [Mongoose 저장 옵션](https://mongoosejs.com/docs/8.x/docs/api/document.html#Document.prototype.save()).
- 전역 10KB parser가 문의 라우트보다 먼저 최대 길이 한글 및 parser 오류를 처리하는 문제를 수정했다. 문의는 라우트의 32KB JSON parser와 공개 오류를 사용하고 다른 경로는 기존 10KB 제한을 유지한다.

## 남은 출시 조건

1. 실제 회사 고지·개인정보처리방침과 수집/보유/삭제 운영을 일치시킨다. 관련 국가의 적용 법 확인은 아직 완료하지 않았다.
2. 충분한 디스크 공간에서 전체 Next production build와 실제 Next 서버의 화면·라우팅·서버 렌더링·배포 origin/CORS 흐름을 검증한다. 현재 드라이브 여유가 약 200MB 수준이어서 대형 앱 빌드 캐시를 생성하지 않았다.
3. 새로고침·다른 탭·브라우저 재시작까지 동일 요청 키를 복구하는 범위는 미구현이다. 현재 키는 화면 메모리에만 둔다. 이 한계를 숨기고 전 상황 중복 방지를 보장하지 않는다.
4. 운영자 알림 실패의 자동 재시도·관찰, 공개 접수 스팸/속도 제한과 배포 인프라 수준의 보호를 준비한다.
5. 쿠키/추적/외부 임베드, 전체 사이트 접근성, 이미지 권리·후기·주장 증빙, 실제 회사 정보, 약관/환불 조건을 중요도 순으로 이어간다.
6. 최신 main과 통합 검수 후 한 PR로 병합한다. 회사 고지 미확정 및 전체 빌드 미검증 상태에서는 draft를 유지한다.

Vercel 프로젝트 조회는 권한 403으로 상세 Git 운영 배포 연결을 확인하지 못했다. 푸시 후 GitHub 상태에서는 `c76c658`의 Vercel 미리보기 배포 완료와 미해결 미리보기 피드백 0건을 확인했다. 이는 이 브랜치의 미리보기 자동 배포가 동작한다는 근거이며 전체 앱 검수·운영 자동 배포 설정의 확인을 대체하지 않는다. 운영 배포 명령은 실행하지 않았다. 이 변경은 공유 checkout의 히어로·14번·다른 섹션을 수정하지 않는다. 리뷰는 수동 소스 검토와 자동 회귀 검사이며 외부 독립 리뷰 승인으로 표현하지 않는다.
