# 문의 중복 방지 인덱스 구조 확인

기준 `73e3584`. 기존 repository는 인덱스 이름, unique 값, inquiryRequestKey 및 문자열 type 조건만 확인했다. 같은 이름의 복합 키나 더 좁은 부분 필터도 통과하므로, 앱이 의도한 전체 요청 키의 중복 방지를 보장하지 못할 수 있었다. 운영 DB에서 이 오구성이 발생했다고 확인한 것은 아니다.

수정은 모델이 선언한 정확한 키·부분 필터 구조를 확인한다. 추가 키, 부분 필터 필드, 중첩 제약을 거부하고 unique는 true여야 한다. v/background 같은 일반 인덱스 메타데이터는 허용한다. 인덱스를 생성·수정·삭제하지 않고 조건 불일치 시 기존 서비스의 저장 불가 경로를 유지한다.

## 검증

- 실제 repository에 FakeModel을 연결한 새 검사에서 수정 전 3실패/3통과: 복합 키, 추가 필터 필드, 중첩 조건의 잘못된 허용 재현.
- 수정 후 6/6 통과. 잘못된 구조는 모델 생성·save 전에 거부, 정확한 구조와 일반 메타데이터는 허용.
- 변경 두 JS/CJS 파일 ESLint와 repository Prettier 통과, diff check 통과.
- `test:contact`에 새 검사 파일을 포함. 기존 문의 DB 검사 20개는 이 수정 후 재실행을 시도했으나 실행 전 메모리 기준에서 중단되어 미실행이다. 이전 20개 통과를 이번 변경의 DB 실측 결과로 쓰지 않는다.
- DB·운영 환경·인덱스 변경 없음. 프런트는 바꾸지 않아 새 화면 캡처·프런트 빌드는 하지 않음.

같은 회사 OpenAI 에이전트의 재현·검토이며 타사 검토를 대체하지 않는다. 실제 DB 검사 재실행과 최신 코드 타사 리뷰를 남기고 Draft를 유지한다.
