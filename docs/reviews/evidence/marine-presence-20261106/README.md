# 해상 화물 식별·수면 후속

기준 앱은 b123e00, 초안 원본은 7b5ade7이다. 사진의 중립 화물, 카메라, 메뉴, 폰트, 도로에서 이어지는 화물 위치와 출항 경로는 유지한다.

## 변경

- 사진 전환 시 전체 stack batch가 숨겨져 주황 화물의 몸체도 사라지던 문제를 수정했다. 같은 좌표·크기의 몸체를 cargo 자식으로 분리하고 원래 instance는 크기 0으로 비활성화한다. 주황 화물은 한 개다.
- 사진 전환 뒤 기존 roof 이미지의 흰색 JSL 글자를 더 크게 표시한다. 새 글꼴이나 외부 로고를 만들지 않는다. 전용 texture clone으로 UV를 분리하며 도로·macro의 기존 지붕 이미지는 바꾸지 않는다.
- 전역으로 이어지던 짧은 파형을 공간별 위상·방향·진폭이 다른 유한 물결 무리로 바꾼다. 기존 12개 주파수 대역은 유지하되 각 대역에서 4개 carrier를 평가한다. 공간별 에너지가 달라지므로 이전 전역 RMS 0.12를 그대로 보존한다고 주장하지 않는다.
- 기존 swell·Kelvin·포말·HDR·+0.25EV·24초/7.2m/s scroll clock은 유지한다. 역방향도 같은 진행률의 결과를 사용한다.

## 근거와 한계

`results.json`은 최종 로컬 Next 운영 빌드의 PC1440×900·모바일390×844 실제 캡처 12장면이다. API 요청은 차단했다. 46/52/58/65/72%와 역방향65%에서 셰이더 오류·넘침·fallback을 검사하고, 비활성 원래 슬롯과 개별 몸체·문자 overlay도 확인한다. 색 슬롯 수만으로 몸체의 가시성을 판단하지 않는다.

`verification.json`은 카메라·시계와 역방향 PNG의 동일성 및 실제 자산 응답 해시를 기록한다. `water-properties.json`은 CPU 해석 미분·경계 연속성 검사이며 시각 품질을 대신하지 않는다. 같은 카메라에서 원본/24/48 carrier를 렌더해 비교하고 48안을 연결했다. 동기화 도구는 water/photo-vessel 원본 fragment 밖 앱 코드를 보존한다.

Next webpack 빌드와 TypeScript 단계, 초안 npm verify(소스 문법76개·daylight 계약8개)가 통과했다. 새 TSX·백엔드 변경이 없어 기존 문의·DB·유닛 전체 검사는 반복하지 않았다. 내부 OpenAI 읽기 검토에서 새 차단 결함은 없었으며 타사 리뷰가 아니다.

초안 inline 한도1MB와 자산 한도를 유지하기 위해 생성 단계에서 두 해상 fragment의 독립 행 주석만 제외했다. Git 원본의 설명은 보존한다. 초안 소스와 Playwright headless runtime은 C: 공간 부족으로 D:에 보존하고 기존 경로를 junction으로 연결했다. Git 연결 검사도 통과했다.

Safari·실기기·GPU 성능·연속 영상은 미검증이다. 짧은 headless 동기 렌더 시간은 기기 FPS 근거로 사용하지 않는다. 운영 병합·배포 및 최종 사용자 시각 승인은 별도다.
