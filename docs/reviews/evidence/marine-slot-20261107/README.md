# 기존 적재 칸의 JSL 컨테이너

기준은 사용자가 거절한 `6c42f76`이다. 이전 결과는 컨테이너 수와 코드 가시성 검사만 통과했으며, 추가3D상자의 크기·원근·접촉이 사진의 적재 칸과 맞지 않았다. 그 결과를 시각 완성으로 보고한 판단을 철회한다. 이전 이미지는 비교 근거로 보존한다.

## 수정

- 사진 위에 따로 그리던 상자 몸체와 문자 평면을 제거했다. 원래 native 배치와 화물은 다시 그대로 사용한다.
- 내장 OpenAI 이미지 편집 도구로 사진 중앙의 기존 흰 컨테이너 한 칸을 주황색 JSL로 바꿨다. 기존 네 모서리·골판 지붕·옆 컨테이너와의 접촉을 따른다. 새 상자를 적재하지 않는다.
- 사진 전환 범위 `.56–.62`는 유지한다. 근접 구간에서는 native 모델을 쓰고, 사진이 완전히 덮이면 화물을 포함한 모든 native 메시를 숨긴다. 사진 실패 시 기존 native 모델이 남고, 역방향에서 다시 나타난다.
- 수면·카메라·운송 동선·메뉴·폰트는 이번 수정에서 바꾸지 않았다.

## 실제 근거

`cargo-before-after.jpg`는 같은 PC 화면 좌표의 실제 캡처를 확대해 나란히 놓은 것이다. 화면 합성으로 컨테이너 위치를 고치거나 새 상자를 그리지 않았다. 왼쪽은 거절된 결과, 오른쪽은 기존 적재 칸을 바꾼 수정본이다.

`transition-1440.jpg`는 실제52/56/58/60/62.5/65% 장면이다. `results.json`은 PC1440×900·모바일390×844, 각9조건을 기록한다. 추가 상자·문자 평면이 없는지, 사진 완료 뒤 native 화물이 숨겨지는지, 실제 자산 응답 해시와 오류·넘침을 확인한다. 이 검사는 사진의 현실감을 대신하지 않으며 확대 캡처를 별도로 검토했다. 첫 실행의 PC5조건은 통과했고62% 경계는 반올림 전 진행률이 종료값보다 작아 엄격한 숨김 검사가 실패했다. 완료 뒤 확인은62.5%로 옮겼으며, 앱 빌드·자산을 바꾸지 않고 남은13조건만 실행해 기존5조건과 합쳤다.

`verification.json`은 같은 진행률에서 비교 가능한9카메라·시계, 수면 셰이더,46% macro PNG 및65% 역방향 PNG 일치를 기록한다. PC58% 캡처는 실제 진행률이0.5799(이전0.58)여서 카메라·시계의 정확한 일치 비교에서 제외했다. 원본 동기화는 카메라와 시계 코드가 바뀌지 않았음을 별도로 확인한다. draw call/triangle 수는 카메라 속성에서 제외했다. 추가 메시를 제거해 해당 수치는 달라진다.

최종 Next webpack 빌드·TypeScript 단계·78개 정적 페이지와 초안 npm verify(소스 문법76개·daylight 계약8개)를 통과했다. 새 TSX·백엔드 변경이 없어 해당 전체 lint·문의·DB 검사는 반복하지 않았다. 같은 회사 내부 읽기 검토는 새 코드 결함을 찾지 못했으며 타사 리뷰가 아니다.

이미지의 전체 캔버스와 알파 범위는 기존1962×838에 맞췄다. 출력178,112bytes WebP는 별도 주황 상자 없이 기존 칸을 포함한다. 프롬프트·변환·해시는 `asset-generation.json`에 있다. 생성 편집이 상속 입력의 권리를 독립적으로 보장하지 않는다.

Safari·실기기·GPU 성능은 미검증이다. 최종 사용자 시각 승인과 운영 병합·배포는 별도이며 PR은 Draft를 유지한다.
