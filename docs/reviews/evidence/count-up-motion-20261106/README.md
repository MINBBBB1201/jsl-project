# 동작 줄이기 전환과 실적 수치

2026-11-06. 실제 로컬 Next 운영 빌드를 Chromium에서 확인했다. API는 합성503으로 접었으며 운영 데이터나 계정은 변경하지 않았다.

## 재현과 수정

기준 앱은 `03bb5c6`이다. 영어1440과 한국어390에서 일반 모션으로 로드한 뒤, 실적이 화면 밖에 있을 때 동작 줄이기를 켜면 숫자가0에 머물렀다. 재생 중 전환하면37에 멈췄다. B안이 새로 만든 회귀는 아니며 기존 CountUp 분기의 결함이다.

설정이 바뀌면 진행 중 재생을 정리한 뒤 목표값을 즉시 표시하도록 수정했다. 기존1.2초·진입40%·한 번 재생·이징과 최종값 aria-label은 유지했다. 레이아웃과 수치·단위는 변경하지 않았다.

마지막 조건은 서버HTML 안의 숫자만 검사한다. JavaScript를 끄면 상위 리빌이 숨기는 전체 섹션의 가시성은 이 검사로 보장하지 않는다. 실제 기기·Safari·스크린리더는 미검증이다.

수정 전후 webpack 컴파일·TypeScript·정적78페이지 빌드가 통과했고 변경TSX lint·도구 구문·diff 검사도 통과했다. 이전 문의·DB 검사는 이 수정으로 반복하지 않았다.

도구는 `tools/landing-review/count-up-motion-check.cjs`이다. `PLAYWRIGHT_MODULE`, `CHROMIUM_EXECUTABLE_PATH`, `REVIEW_BASE_URL`, `REVIEW_OUTPUT`으로 설치된 런타임과 로컬 서버를 지정한다. 새 패키지를 설치하지 않았다. 수정 후 재생 중 검사는 중간값1부터100까지만 받아 설정 전환 전에 끝나 버리는 오탐을 줄였다. 원본 재현37은 이 범위에도 들어간다.

초기 도구 보정에서 모바일 하이드레이션 전 최종값을 잘못 읽었고, JavaScript 없는 섹션을 스크롤하려 해 실패했다. 최종 증빙은 실제0 상태를 기다리며, 서버HTML은 값만 확인한다. 이 보정 실패를 앱 결함이나 최종 통과로 계산하지 않았다.

`before.json`과 `after.json`에 LF 정규화한 CountUp 소스SHA-256, 조건별 결과와 페이지 오류를 기록했다. 캡처는 설정 전환 뒤의 실제 화면이며 `compare-en.png`는 같은 크기의 두 캡처를 축소해 나란히 배치한 것이다.

공식 동작 근거: [React effect cleanup](https://react.dev/reference/react/useEffect), [Motion animation controls](https://motion.dev/docs/animate). OpenAI 내부 검토는 다른 회사 모델의 교차 리뷰로 계산하지 않는다. 운영 병합·배포는 수행하지 않았다.
