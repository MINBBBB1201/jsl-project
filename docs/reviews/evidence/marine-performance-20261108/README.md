# 선박 연결·성능 보정

기준 앱은 `d5b5f8874679f593e22ab8f13e9b931cd76944e2`다. 사용자가 히어로가 아니라 선박 자체의 어색함과 페이지 렉을 지적해 해상 장면을 다시 확인했다. 기존 메뉴·글꼴·카메라·단일 주황 컨테이너·물결과 운송 동선을 보존했다.

## 실제 원인과 수정

1. 사진 실루엣을 높이12.1m에서 수면으로 다시 투영한 그림자가 선체와 떨어져 보였다. 같은 등록 평면 바로 아래6cm·불투명도0.12의 접지 그림자로 바꿨다. 사진이 표시될 때 사라진 native 선체의 수면 그림자·주변 어둡게 하기도 끈다. 물결 주파수·색·항적 계산은 바꾸지 않았다.
2. 사진 속 주황 칸이 native 칸과 길이 방향 약0.92m, 폭 방향 약0.29m 어긋났다. 사진 전체를 실제 native roof 모서리에 positive affine으로 맞췄다. 새 상자를 올리거나 선박을 거울 반전하지 않았다. 네 번째 모서리는0.0754m 미만, 원본 paint UV는4.4e-14 미만 오차다.
3. 형태가 다른 두 선교를56–62%에서 투명 혼합해 두 겹으로 비쳤다.57.5%에서 한 소스만 표시하는 화물 기준 match-cut으로 바꿨다. 정·역방향 기준은 같고 사진 미로딩·실패 시 native를 유지한다. 사진 선체는 여전히 평면이므로 완전한3D 재구성이 아니다. 경계 순간의 선체 형태 변화는 후속 시각 검수 대상으로 남긴다.
4. 해상 이전에도 WebGL·선박·HDR 준비를 시작하고, 페이지를 떠난 뒤 전역 이벤트가 이전 엔진을 붙잡았다. 해상 직전 준비와 `ucDispose` 정리를 추가했다. 화면 밖·숨겨진 탭에서는 해상 렌더를 건너뛰며, 탭이 돌아오면 다시 갱신한다.
5. 숨겨진 도로의 SVG 경로·길이·점을 반복 계산했다. 화면 크기와 진행률에 따라 캐시를 갱신한다. WebGL 해상도는 PC DPR1, 모바일1.25, 총160만 픽셀 이내로 제한한다. HTML 글자는 장치 해상도를 유지한다. 선박·수면 캔버스의 실제 픽셀 수를 줄인 것이며 화질이 모든 기기에서 동일하다는 주장은 하지 않는다.

## 검사와 한계

- 최종 webpack 컴파일·TypeScript·78정적페이지, 변경 TSX ESLint, 모듈 문법과 diff 검사 통과.
- 초안 `npm run verify`:76문법·8daylight 계약, inline995,068bytes 통과. 화면 품질 보증 검사가 아니다.
- 순수 Three 등록2조건과 각9개 전환 경계 왕복 관측, 사진 미로딩 fallback 확인. 물 소스는 그림자 소유권 변경 외 파형·색·항적이 동일함을 검사했다.
- 실제 PC1440×900 DPR1·모바일390×844 DPR2,58/65/역58%의6상태: 오류·가로 넘침·fallback0, 사진 opacity1, native 그림자 값0. 양쪽 역58% PNG가 정방향과 같다.
- 모바일에서 동작 줄이기를 켜면 이전 guest가 제거되고 render 함수가 지워지며 GPU context loss가 확인됐다.
- 마지막 뷰포트·탭 가드는 최종 빌드에서 별도로 확인했다. 위·아래 화면 밖 렌더0, 숨김 상태 렌더0, 표시 복귀 렌더1, 활성 해상6호출·fallback0, Next 이동 뒤 render 제거·GPU context loss 확인. 숨김/표시 상태는 브라우저에서 합성한 입력이므로 실제 탭 백그라운드·기기 시험과 구분한다. `visibility-results.json` 참고. 기존 캡처는 같은 선체·재질·카메라지만 새 가드의 실행 증거로 계산하지 않는다.
- 기존 전체 유닛·문의 DB 검사는 반복하지 않았다. Safari·실기기 FPS·INP·최신 Vercel·운영 배포, 최신 변경분 타사 검토는 미확인이다. 내부 OpenAI 검토는 타사 리뷰가 아니다.

현재 선박·성능을 완성 승인으로 표시하지 않는다. 사진 기반 선체의 깊이 한계와 실제 전환 경계·기기별 스크롤 성능을 더 확인해야 한다. 유료 업스케일·비행기/구름 생성·회사 정책 입력·운영 DB·계정·main 병합·운영 배포는 하지 않았다.

재현 도구는 실행한 사본에서 모듈·실행 파일 경로만 환경 변수로 바꿨다. `JSL_PLAYWRIGHT_MODULE`, `JSL_CHROMIUM_EXECUTABLE`, `JSL_THREE_MODULE`, `JSL_PROTOTYPE_ROOT`를 로컬 설치에 맞춘다. `capture-evidence.cjs`는 캡처 도구의 출력 경로 오타를 수정한 사본이며 기록 폴더의 기존 결과를 덮어쓰므로 먼저 보관한다. `lifecycle.cjs after`, `visibility-check.cjs`, 두 순수 검사를 각각 실행할 수 있다. 테스트 과정의 중간 캡처·GPU 동기화 시도는 최종 통과 숫자에 섞지 않았다.
