# 직원 아이디 로그인

기존 이메일 계정에 선택적 아이디를 추가한다. 이메일 로그인·토큰·권한은 유지한다. 로그인 요청의 기존 `email` 필드는 아이디 또는 이메일을 받는다. 새 API 필드를 강제하지 않아 기존 클라이언트도 사용할 수 있다.

아이디는 영문·숫자로 시작하며 영문·숫자·점·밑줄·하이픈 3-32자를 허용한다. 저장과 조회는 소문자로 정규화한다. 아이디가 없는 기존 계정은 그대로 유효하다. 사용자 모델은 문자열 아이디만 대상으로 하는 부분 고유 인덱스를 정의한다. 중복 발급은 409이며 기존 계정 정보는 덮어쓰지 않는다.

로그인 폼은 아이디 또는 이메일을 받는다. 관리자 직원 발급 폼에는 선택적 아이디를 추가한다. 이메일은 계속 필수이며 계정 발급은 기존 관리자 권한 검사를 거친다.

## 기존 계정 설정

`backend/src/scripts/set-account-login.js`는 표준 입력의 JSON 객체에서 `email`, `username`, `password`를 받는다. 비밀번호를 명령 인자·소스·파일·로그에 넣지 않는다. 실행 전 해당 운영 환경과 대상 계정을 확인해야 한다.

이 도구는 기존 계정을 찾고 아이디 고유 인덱스가 준비됐는지 확인한다. 아이디·해시한 비밀번호만 한 번의 원자적 갱신으로 저장한다. 이름·이메일·역할·활성 상태는 바꾸지 않으며 계정이 없으면 생성하지 않는다. 중복 아이디로 갱신에 실패하면 기존 비밀번호도 유지된다. 비활성 계정은 재설정 후에도 로그인할 수 없다.

이번 구현에서 실제 운영 계정 설정이나 DB 인덱스 적용은 실행하지 않았다. 지정한 사용자 값은 커밋하지 않았다.

## 검증

- 프런트 전체 TypeScript와 변경 3파일 ESLint 통과.
- 백엔드 변경 파일 ESLint 통과.
- 초기 아이디 HTTP·MongoDB 회귀 검사 10개 통과. 기존 백엔드 전체 검사 7스위트·170개 통과.
- 기존 계정 설정·중복 시 원자성 검사 2개를 추가했고 최종 전체 재검사 결과는 PR 댓글에 기록한다.
- 임시 MongoDB와 기존 바이너리·의존성만 사용했다. 새 설치·다운로드·운영 DB·실제 계정은 사용하지 않았다.
- React 검토에서는 기존 폼·라벨·자동완성·오류 처리와 로그인 후 복귀 흐름을 보존했는지 확인했다. 실제 프리뷰 화면·원격 빌드·타사 검토는 별도로 기록한다.

## 배포 조건

백엔드를 먼저 반영해 이메일/아이디 입력을 수용하고 고유 인덱스가 준비됐는지 확인한 뒤 프런트를 반영한다. 새 프런트를 이메일 전용 백엔드에 먼저 연결하면 아이디 로그인은 실패한다. 실제 계정 설정은 배포 확인 후 실행한다. 인덱스 생성 실패·이전 아이디 데이터와 충돌이 있으면 운영 설정을 중단한다.

교차 검토 전 Draft를 유지한다. 병합·운영 배포는 별도 사용자 승인 절차를 따른다. 실제 로그인·모바일/다크 화면·직원 발급의 운영 쓰기는 이 보고서에서 통과로 주장하지 않는다.

## Claude 검토 후 보완

Claude Opus 5.5(Anthropic)가 초기 head `64f75dd`의 9파일을 읽기 전용으로 검토했다. 새 차단 결함은 없었고 낮은 등급의 두 지적을 보완했다. 관리자 아이디 발급 경로도 고유 인덱스가 없으면 쓰기 전에 503으로 차단한다. 계정 설정 도구와 같은 검사 함수를 공유한다. 인덱스를 제거한 임시 DB에서 발급·계정 설정이 모두 중단되고 데이터가 늘지 않는 회귀 검사를 추가했다.

계정 설정 도구는 허용한 실패 코드만 출력한다. 입력 오류·계정 없음·인덱스 미준비·중복과 그 밖의 실패를 구분하며 원문 오류·비밀번호는 출력하지 않는다. 추가 변경은 최신 SHA의 재검토 대상이다.

보완 후 백엔드 전체 7스위트·173개와 변경 파일 ESLint가 통과했다. 프런트는 보완에서 바뀌지 않았다. 초기 head의 실제 프리뷰에서 아이디 입력란과 비밀번호 필수 검증을 확인했다. 원격 빌드와 최신 변경분 검토는 PR의 정확한 SHA로 구분한다.

검토자가 지적한 Gmail 정규화 문제는 기존 관리자 발급 API의 저장 경로에는 그대로 적용되지 않는다. register 라우트에도 normalizeEmail이 있어 일반 API 발급·로그인은 같은 정규화를 거친다. seed 또는 외부에서 직접 만든 계정의 주소 표기 불일치는 별도 확인 대상이며 이번 PR의 새 결함으로 주장하지 않는다.

근거: [MongoDB 고유 인덱스](https://www.mongodb.com/docs/manual/core/index-unique/), [Mongoose 스키마 인덱스](https://mongoosejs.com/docs/guide.html#indexes). 고유 제약은 입력 검증만으로 대체하지 않는다.
