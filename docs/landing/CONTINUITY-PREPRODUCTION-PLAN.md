## 1. 문제를 구분하기

### 직접 관찰한 것

- 기존 JSL 히어로는 어두운 여백, 큰 지구 곡면, 대형 타이포가 화면을 지배한다.
- 현재 첫 장면은 선박·크레인·컨테이너 야드·비행기·공항 시설이 있는 배경과 별도 전경 트럭이 화면을 채운다.
- 현재 전환 52% 캡처에는 왼쪽의 야간 사진과 오른쪽의 낮 항만 사진 사이에 수직 경계가 있다. 제목이 두 배경 위에 걸친다.
- United Carriers의 흰 장비 구간은 여백과 분리된 장비가 중심이다. 이번 재관찰은 해당 구간의 일부 상태에 한정되며, 전체 사이트 애니메이션을 새로 검증한 것은 아니다. [원본](https://unitedcarriers.com/)
- 현재 트럭 자산은 하나의 투명 배경 이미지다. 구현은 이미지 이동·확대와 배경 전환을 사용하는 2.5D 방식이다. 바퀴 회전, 차량 회전, 실제 운반 시뮬레이션은 구현되어 있지 않다.
- 항만·창고·트럭 이미지는 이전 작업의 생성 자산이다. 실제 JSL 현장 사진이 아니다.

### 디자인 판단 / 아직 검증할 가설

- “AI 같다”는 인상에는 장면에 많은 시설이 동시에 등장하는 구성, 전경과 배경의 시점·빛 차이, 장면 사이 공간의 단절이 영향을 주는 것으로 판단한다.
- 새 배경의 디테일을 더 만드는 것보다 **장면의 위계와 연결을 먼저 확정**해야 재작업이 줄어든다.
- “실제 현장” 방향을 선택한 것은 실사 질감의 선호로 해석한다. 모든 구간을 전체 화면 항만/창고 사진으로 바꾸라는 승인으로 확대하지 않는다.
- 완전히 흰 배경으로 바꾸는 것 역시 아직 제안이다. 기존 템플릿의 전체 구도와 비교한 뒤 결정한다.

## 2. 승인된 내용과 새 제안

### 기존 기준

- 애니메이션 흐름의 기준은 United Carriers다.
- 한 슬라이드에는 하나의 레퍼런스의 전체 구도를 적용한다.
- 서비스는 Emons, 화물 과정은 Freezpak 등 기존에 합의한 장면 대응을 기준으로 한다.
- JSL 고유 콘텐츠, 로고, 동일 화물 표현을 사용한다.
- 히어로와 14번 장면은 이번 작업 대상이 아니다.

### 이번에 제안하는 것

- 먼저 **첫 교체 장면과 그 다음 장면의 연결 한 구간**을 제작 전 검증 대상으로 삼는다. 현재의 운송수단·화물 과정 두 슬롯이다.
- 전체 사이트를 동시에 재설계하지 않고, 전체 장면 지도와 공통 규칙을 먼저 적는다. 이후 사용자에게 선택받은 두 장면 초안만 실제로 구현한다.
- 새 디자인의 차이는 JSL 자산·내용·색 사용과 장면 사이 연결에서 먼저 만든다. 승인된 화면 구도를 여러 레퍼런스의 요소로 해체하지 않는다.

## 3. 전체 장면 지도 — 기존 구도를 유지할 기준

이 표는 새 구현 목록이 아니다. 첫 두 장면 이후의 작업은 별도 범위 확정이 필요하다.

| 장면 | 전체 구도의 기준 | 연결에서 검토할 것 | 실제 제작 전에 필요한 자료 |
|---|---|---|---|
| 히어로 | 현재 JSL / United Carriers | 현재 퇴장 상태와 다음 장면의 배경·대비 | 기존 실제 퇴장 캡처. 수정 없음 |
| 운송수단 | Emons의 서비스 01–05 | 미디어의 크기와 서비스 선택 상태 | 사용할 원본 구간의 전체 화면, JSL 5개 모드 내용 |
| 화물 과정 | Freezpak의 단계 전개 | 운송수단 화면에서 과정 화면으로 넘어가는 경계 | 원본 단계의 전체 화면과 각 단계 매체 |
| 네트워크 | Nash | 화물 상태와 거점 선택의 시간적 연결 | 실제 거점 좌표, 표시 가능한 데이터 |
| 창고·운영 | Gather AI | 공간 시점과 데이터 레이어의 밀도 | 실제 창고 매체 또는 일관된 모델 |
| 트럭 | Truck’N Roll | 차량이 주인공이 되는 화면과 출발 타이밍 | 해당 전체 장면의 구도, 차량 시점 |
| 시스템·관제 | Optimal Dynamics | 제품 화면 크기와 읽기 시간 | 실제 JSL 제품 화면·허용된 데이터 |
| 회사 신뢰 | Viamaster | 실제 현장 매체와 회사 정보 | 실제 출처와 사용 범위가 확인된 JSL 사진 |

공통 헤더/진행 UI는 현재 한 세트를 유지한다. 참조 사이트별 헤더를 중복 삽입하지 않는다. 전체 남색 배경, 반복 카드 그리드, 장식용 데이터 패널을 새 공통 틀로 만들지 않는다.

## 4. 순서와 산출물

### 단계 A — 기준 화면 명세

**코드 수정 전에** 원본·현재 화면에서 다음을 기록한다.

1. 각 장면의 정확한 시작/종료 지점과 인접 장면.
2. 제목·본문·장비·미디어 영역의 위치와 크기를 화면 비율로 기록.
3. 여백, 흰/검은 면적, 텍스트와 장비 중 무엇이 주도하는지.
4. 들어오는 방향, 멈추는 상태, 나가는 방향, 화면 고정 여부.
5. 모든 항목을 `관찰 / 제안 / 미확인`으로 구분.

**통과 조건:** 사용할 원본의 전체 구도가 정확히 지정되고, 유지/교체 목록이 모호하지 않아야 한다. “비슷하게”, “고급스럽게”만 적은 명세로 구현을 시작하지 않는다.

### 단계 B — 정지 초안

- 첫 운송수단 장면을 두 방향까지만 비교한다.
  - **기존 승인 구도 보존안:** Emons 전체 구도에 JSL 콘텐츠와 실제 매체 후보를 적용한다.
  - **UC 연결 조정안:** 같은 전체 구도를 유지하며 사진의 점유율·크롭·명암과 앞뒤 경계만 조정한다. 흰/검은 배경의 큰 변경이 필요하면 그 자체를 별도 표시하고 선택받는다.
- 항만·공항·기차·트럭이 동시에 보이는 새 합성 배경을 추가하지 않는다.
- 초안 화면과 실제 앱 캡처를 명확히 구분한다.
- 데스크톱 1440×900과 모바일 390×844에서 **앞 장면 마지막 / 서비스 진입 / 서비스 읽기 / 연결 중간 / 과정 진입** 다섯 상태를 만든다.
- 선택되지 않은 방향을 이후 구현에 혼합하지 않는다.

**통과 조건:** 사용자에게 어느 구도와 매체를 선택하는지 확인받는다. 자산이 어색하면 이 단계에서 교체한다. 정지 화면의 완성도가 부족한 상태를 애니메이션으로 덮지 않는다.

### 단계 C — 짧은 모션 초안

- 실제 랜딩과 분리된 검토용 프로토타입에서 5개 상태를 연결한다.
- 정상 속도 8–12초 영상과 수동으로 진행률을 움직일 수 있는 검토 화면을 만든다. 길이는 제안이며 원본 관찰 후 조정한다.
- 전진·역방향에서 같은 상태가 재현되어야 한다.
- 서로 다른 낮/밤 사진의 수직 와이프는 일단 보류한다. 시점이 이어지지 않으면 읽기 상태 이후 짧은 컷으로 전환하는 안을 비교한다.
- 같은 트럭이 계속 등장한다면 동일 자산·크기·진행 방향을 유지한다. 새로운 시점이 없으면 회전으로 표현하지 않는다.
- 첫 단계의 화물 운반이나 14번 장면 수정은 이 프로토타입에도 추가하지 않는다.

**시간 배분 초안:** 앞 장면 경계 0–15%, 서비스 진입 15–30%, 읽기/선택 30–55%, 연결 55–75%, 과정 진입/읽기 75–100%. 원본의 타이밍을 새로 측정한 수치가 아니라 비교를 위한 시작값이다.

**통과 조건:** 순간 잘림, 겹친 제목, 장비의 갑작스러운 크기 변화, 이동 방향 반전, 읽기 상태 없는 통과, 빈 화면이 없어야 한다. 정지 초안에서 선택한 구성과 같아야 한다.

### 단계 D — 실제 구현

선택된 초안·모션과 수정할 파일 목록이 확정된 뒤에만 진행한다.

- 현재 두 슬롯을 담당하는 `industrial-journey.tsx`, `industrial-scenes.tsx`, `industrial-motion.ts`, `industrial-journey.css`가 우선 검토 대상이다. 실제 변경 대상은 선택한 초안에 맞춰 다시 명시한다.
- 기존 Emons/Freezpak 컴포넌트와 자산은 보존되어 있다. 원본 구도로 복원하는 안을 선택하면 해당 슬롯 연결만 변경한다. 지금 복원하지 않는다.
- 헤더·히어로·14번·다른 슬라이드·라우팅·API·메시지 구조·전역 스타일은 이번 변경 후보에서 제외한다.
- 기존 GSAP/ScrollTrigger를 사용한다. 새 라이브러리나 앱 전역 스크롤 제어는 이 계획의 필수 조건이 아니다.
- 수정 전의 현재 소스 해시와 캡처를 별도로 저장한다. 과거 체크포인트를 덮어쓰거나 사용자 변경을 자동 롤백하지 않는다.

### 단계 E — 검수 및 완료 보고

- 1440×900, 390×844에서 선택한 5개 상태와 원본/초안/실제 구현을 나란히 비교한다.
- 전체 구간을 2% 간격으로 확인하고 경계 주변은 더 촘촘하게 확인한다.
- 정방향·역방향·리사이즈·reduced motion과 4개 로케일의 링크/레이아웃을 확인한다.
- 장비 접촉이 필요한 별도 작업에는 같은 좌표계에서 시작·들기·적재·출발 검수를 적용한다. 사진 교차 페이드로 접촉/회전을 증명하지 않는다.
- 구현 후에만 tsc/lint/build/기존 테스트를 실행한다. 빌드 통과와 디자인 승인 여부를 별도 항목으로 보고한다.
- 완료 보고는 `완료 / 남음 / 보존 확인 / 실제 캡처·영상 / 테스트 / 지시와 다르게 판단한 부분 / 한계`를 한 번에 정리한다.

## 5. 외부 도움과 도구의 역할

| 수단 | 맡길 일 | 이번 상태 / 선택 조건 |
|---|---|---|
| Figma | 같은 크기의 전체 화면 비교, 크기·여백 기록, 정지 초안 편집 | 계정 조회 성공. 파일 생성·편집은 아직 하지 않았으므로 가능하다고 확정하지 않음. 현재 View 좌석 상태를 먼저 확인해야 함 |
