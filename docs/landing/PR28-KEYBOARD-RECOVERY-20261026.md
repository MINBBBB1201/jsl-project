# 운송 여정 키보드·로딩 실패 복구 검수

기준 head는 `f18abfc57b13c7e09f5ba025e959c49e9ded895a`다. 해당 소스에서 서비스 링크 초점 유실과 본체 청크 실패의 빈 장면을 재현했다. 후속 검사에서는 지연 로딩 완료 후 건너뛴 장면으로 되돌아가는 경로도 재현해 보완했다. 선박·화물·카메라·전환 타이밍을 계산하는 생성 모듈은 변경하지 않았다.

## 수정한 동작

- 엔진은 서비스 설명 영역에 `inert`를 적용한다. 기존 코드는 엔진을 그린 뒤 링크의 초점을 확인해서, 이미 초점이 본문으로 떨어진 경우를 놓쳤다. 이제 엔진을 그리기 전에 초점을 기억하고, 링크가 비활성 영역에 들어가거나 제거되면 Skip journey로 옮긴다.
- 본체 청크를 받지 못하면 기존 화면은 빈 장면이었다. 이제 이 오류 상태에서만 상태 안내와 Skip journey 버튼을 표시한다. 엔진이 이미 로드된 GSAP 실패 경로는 기존 건너뛰기를 유지한다.
- 로딩 중 건너뛰면 대기 중인 앵커 이동을 무효화한다. 나중에 pin을 삽입하거나 refresh할 때 이미 도달한 다음 콘텐츠의 화면 위치를 보존한다. 사용자가 다시 앵커로 돌아가거나 수동으로 역스크롤하면 건너뛰기를 강제하지 않는다. 다음 링크의 초점과 읽기 위치도 보존한다.

## 재현 순서

1. 운송 장면 앵커로 이동하고 서비스 설명이 상호작용 가능한 위치에서 서비스 링크에 키보드 초점을 둔다.
2. 설명 영역이 비활성화되는 지점을 넘긴다. 초점은 본문 대신 Skip journey에 있어야 한다.
3. Enter로 건너뛴 뒤 Tab을 누른다. 다음 콘텐츠의 링크로 진행해야 한다.
4. GSAP 청크 응답을 지연하거나 차단하고 Skip을 다시 확인한다.
5. 별도로 본체 운송 청크를 차단한다. 빈 장면 대신 안내와 Skip이 나오고 키보드로 다음 섹션에 도달해야 한다.

## 한계와 증빙

검수 화면은 주변 섹션을 단순화하고 Next Link/Image 어댑터를 사용한다. 메모리 사용을 줄이려고 Three.js 요청을 차단해 기존 정적 대체 경로를 사용했다. 따라서 실제 선박 렌더, 통합 Next 라우팅, Safari·실제 휴대폰 검수 결과가 아니다. 정상 상태의 디자인 통일이나 재질 품질을 변경·재검수한 작업도 아니다.

실제 PR 미리보기의 최초 방문에서는 운송 섹션이 화면 아래에 있고 아직 생성되지 않았음을 확인했다. 이후 동적 청크 요청은 검수 브라우저에서 Vercel 로그인으로 연결됐다. 같은 파일은 인증된 연결에서 200 JavaScript였으므로 파일 누락이나 앱 404로 판정하지 않았다. 배포에서 위 18조건이 통과했다고 표현하지 않는다.

로컬 재현 도구와 전후 초점 기록, JSON 및 화면은 `D:/jsl-validation/pr28-regression-20261026/`에 있다. 최종 18조건은 `async-recovery-1440.json`, `async-recovery-390.json`이다. 이전 8조건과 재현 자료는 별도로 보관했으며, `review-followup-390.json`에는 수정 전 지연 완료 후 초점이 운송 섹션으로 돌아간 결과가 있다. 비밀값이나 인증 쿠키는 증빙에 저장하지 않았다.

독립 교차 리뷰와 최종 통합 배포 검수는 남아 있다. PR은 Draft를 유지한다.

별도 Codex 세션이 `5312293`의 변경 3파일과 기존 증빙을 읽기 전용으로 재검토했다. 대비와 지연 완료 경로의 이전 지적은 해결됐고, 새로 지적할 명백한 코드 결함은 없다는 결과를 받았다. 해당 세션은 새 검사를 실행하지 않았으며, 같은 회사의 보조 검토를 외부 회사·사람의 승인이나 실제 배포 검수로 표현하지 않는다.

초기 8조건은 GSAP 응답을 보류한 동안의 건너뛰기까지만 확인했다. 그 한계를 보조 리뷰에서 대조한 뒤 지연 완료 경로를 추가로 재현하고 위 18조건으로 확장했다. 빠른 동작 줄이기 전환과 로딩 중 언마운트는 별도 후속 조건이다. 모든 비동기 경로가 통과했다고 표현하지 않는다.
