# 운송 여정 키보드·로딩 실패 복구 검수

기준 head는 `f18abfc57b13c7e09f5ba025e959c49e9ded895a`다. 해당 소스에서 서비스 링크 초점 유실과 본체 청크 실패의 빈 장면을 재현한 뒤 두 경로를 보완했다. 선박·화물·카메라·전환 타이밍을 계산하는 생성 모듈은 변경하지 않았다.

## 수정한 동작

- 엔진은 서비스 설명 영역에 `inert`를 적용한다. 기존 코드는 엔진을 그린 뒤 링크의 초점을 확인해서, 이미 초점이 본문으로 떨어진 경우를 놓쳤다. 이제 엔진을 그리기 전에 초점을 기억하고, 링크가 비활성 영역에 들어가거나 제거되면 Skip journey로 옮긴다.
- 본체 청크를 받지 못하면 기존 화면은 빈 장면이었다. 이제 이 오류 상태에서만 상태 안내와 Skip journey 버튼을 표시한다. 엔진이 이미 로드된 GSAP 실패 경로는 기존 건너뛰기를 유지한다.

## 실행 결과

실제 React 래퍼·생성 엔진·GSAP를 로컬 HTTP 검수 화면에서 실행했다. PC 1440×900과 모바일 390×844에서 아래 네 조건씩, 총 8조건을 확인했다.

| 조건 | 확인한 결과 |
| --- | --- |
| 정상 로딩 | 첫 화면에서 동적 운송 모듈 요청 없음. 앵커 상단 0px 및 섹션 초점. 서비스 링크 비활성화 후 Skip 초점. Enter로 다음 섹션 이동 후 Tab이 다음 링크로 진행 |
| GSAP 응답 지연 | GSAP 요청 두 개를 보류한 상태에서도 Skip과 다음 섹션 초점 이동 정상 |
| GSAP 요청 실패 | Skip과 다음 섹션 초점 이동 정상 |
| 본체 모듈 요청 실패 | 상태 안내와 Skip 하나 표시. Enter로 다음 섹션 초점 이동 정상 |

8조건에서 페이지 JavaScript 오류는 없었다. 모바일 오류 안내 화면도 직접 확인했다.

- `next typegen`: 통과. 새 작업 폴더에 없던 프레임워크 타입을 생성했다.
- `tsc --noEmit --incremental false`: 통과. 처음 512MB 힙 제한에서는 메모리 부족으로 중단됐고, 타입 생성 후 1024MB 제한으로 완료했다.
- 변경 TSX 파일 ESLint: 통과.
- `git diff --check`: 통과.
- 로컬 검수 화면 webpack 빌드: 통과. Next 운영 빌드는 아니다.

## 재현 순서

1. 운송 장면 앵커로 이동하고 서비스 설명이 상호작용 가능한 위치에서 서비스 링크에 키보드 초점을 둔다.
2. 설명 영역이 비활성화되는 지점을 넘긴다. 초점은 본문 대신 Skip journey에 있어야 한다.
3. Enter로 건너뛴 뒤 Tab을 누른다. 다음 콘텐츠의 링크로 진행해야 한다.
4. GSAP 청크 응답을 지연하거나 차단하고 Skip을 다시 확인한다.
5. 별도로 본체 운송 청크를 차단한다. 빈 장면 대신 안내와 Skip이 나오고 키보드로 다음 섹션에 도달해야 한다.

## 한계와 증빙

검수 화면은 주변 섹션을 단순화하고 Next Link/Image 어댑터를 사용한다. 메모리 사용을 줄이려고 Three.js 요청을 차단해 기존 정적 대체 경로를 사용했다. 따라서 실제 선박 렌더, 통합 Next 라우팅, Safari·실제 휴대폰 검수 결과가 아니다. 정상 상태의 디자인 통일이나 재질 품질을 변경·재검수한 작업도 아니다.

실제 PR 미리보기의 최초 방문에서는 운송 섹션이 화면 아래에 있고 아직 생성되지 않았음을 확인했다. 이후 동적 청크 요청은 검수 브라우저에서 Vercel 로그인으로 연결됐다. 같은 파일은 인증된 연결에서 200 JavaScript였으므로 파일 누락이나 앱 404로 판정하지 않았다. 배포에서 위 8조건이 통과했다고 표현하지 않는다.

로컬 재현 도구와 전후 초점 기록, JSON 및 화면은 `D:/jsl-validation/pr28-regression-20261026/`에 있다. `local-results-1440.json`, `local-results-390.json`, `before-fix-focus-before.json`, `before-fix-focus-after.json`, `before-engine-fallback-results.json`을 구분해 보관했다. 비밀값이나 인증 쿠키는 증빙에 저장하지 않았다.

독립 교차 리뷰와 최종 통합 배포 검수는 남아 있다. PR은 Draft를 유지한다.
