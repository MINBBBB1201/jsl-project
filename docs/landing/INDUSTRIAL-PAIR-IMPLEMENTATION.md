# 운송수단 → 화물 과정 · 실제 현장 방향

## 작업 범위

- 사용자 승인: 비교 초안을 실제로 구현하고 애니메이션을 연결한다. 첫 대상은 앞서 제안한 운송수단 → 화물 과정 두 구간이다.
- 적용 방향: 앞서 표시한 A ‘실제 현장’ 정지 시안. 두 방향 중 별도의 A/B 답변은 없었으므로, 작업 시작 메시지에서 실제 현장 방향을 명시하고 진행했다.
- 보존: 히어로, 14번 장비, 나머지 섹션, 기존 레퍼런스 컴포넌트/자산, 라우팅, i18n 구조, API, 백엔드, 패키지 및 글로벌 설정.
- 브랜치: `codex/landing-industrial-pair`. 사용자가 갖고 있던 미커밋 변경은 보존했다.

**매체는 2.5D다.** 배경 두 장과 투명 차량 한 장의 공간 이동/확대를 사용한다. 실제 차량 3D 회전, 바퀴 회전, 집게 작업, 화물 리프팅, 창고 내부의 기계적 처리를 구현한 결과가 아니다. 동일 컨테이너와 트레일러가 한 이미지 안에 있어 분리/겹침을 피한다. 14번 장비 동작은 범위 밖이다.

## 지시와 다르게 판단한 부분

1. 실제 현장 방향에서 사진 같은 장비를 우선하기 위해, 품질 미달 무료 3D 모델을 제외하고 2.5D 차량 자산을 사용했다. 전체 3D 기계 동작 완성으로 보고하지 않는다.
2. 기존 영어 문구 사용 허용에 따라 서비스 5개와 과정 7단계 영어 문구를 유지했다. 메시지 파일/로케일 구조는 변경하지 않았고 상세 링크는 기존 i18n Link를 사용한다.
3. 모바일의 제목 위치가 같아 두 제목을 교차 페이드하면 겹친다. 모바일 제목은 시점에 맞춰 교체하고 차량/배경 이동은 연속 유지한다.

## 남은 일과 제한

- C드라이브 여유 공간 0으로 전체 빌드·실제 사이트 최종 녹화를 완료하지 못했다. 캐시를 삭제하지 않고 NTFS 압축해 약 500MB를 확보했으나 빌드 중 다시 소진됐다. 전체 완료로 보고하지 않는다.
- 마지막 확인에서는 약 321MiB가 남았다. 실패한 빌드를 반복하지 않고 추가 여유 공간 확보 후 전체 빌드를 다시 확인해야 한다.
- 캐시 삭제/남은 검수용 브라우저 강제 종료 명령은 자동 승인 검토에서 `blocked by policy`로 거절됐다. 더 자세한 사유는 반환되지 않았다.
- 별도 모션 검수 주소는 `http://localhost:4314/`이며 `Play 18s`로 확인한다. 실제 랜딩 서버와 구분한다.
- 개발 서버를 다시 시작해 `/landing` HTTP 200과 새 컴포넌트 포함을 확인했다. 디스크 저장 오류는 계속 발생하므로 서버의 완전한 복구로 판단하지 않는다. 브라우저 재확인은 URL 정책 차단(`URL protocol is not allowed`)으로 중단했다. 다른 브라우저로 우회하지 않았다.
- 마지막 수정 후 tsc(`--noEmit --incremental false`)와 변경 TS/TSX 3개 ESLint를 재실행해 exit 0을 확인했다.
- 기존 전체 페이지의 API 5000 연결 실패와 WebGL 경고, 로케일별 HTML lang이 ko인 문제는 범위 밖이므로 보존했다.
- 차량 바퀴는 회전하지 않는다. 2.5D 공간 이동의 시각 검수 통과를 실제 기계 동작 검증으로 주장하지 않는다.
